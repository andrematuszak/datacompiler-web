# Processing result contract

The site keeps one upload box visible while a job runs. When the result is ready,
the API returns the original first-page PNG, document statistics, review states,
and the type-specific translation preview.

The existing asynchronous endpoints remain:

1. `POST /upload` with multipart field `file` returns `{ "job_id": "..." }`.
2. `GET /status/{job_id}` returns `{ "state": "running" | "done" | "error" }`.
3. `GET /result/{job_id}` returns the result object once the job is done.

## Scan-only document

For pages routed as full-page scans, the right-hand panel fades between two
white-page PNGs typeset from UTF-8 text: the source-language VLM transcription
and its translation. Each PNG keeps its opening lines readable and blurs the
lower portion. Neither PNG contains the source scan. The client holds the
paywall in a fixed position over the animation.

`document.kind` distinguishes `printed_scan`, `handwriting`, neutral `scan`,
and `other`. Printed scans do not use the handwriting animation. The client
shows green OCR boxes only when `preview.word_boxes` is present and
`preview.box_granularity` is `"word"`; older responses may provide
`document.word_boxes`.

Per-format reductions are reported by `document.output_formats`; each entry
contains `generated`, `file_size_bytes`, and `reduction_percent`. Each
translation may provide its own `reduction_percent` alongside
`estimated_word_count`. These percentages compare actual output PDF bytes with
the uploaded file bytes. Reduction values may be negative or `null`; the
client hides unavailable measurements rather than substituting a value.
`document.reduction_percent` and `document.size_reduction_basis` are a legacy
default-format summary, not a substitute for the per-format measurements.

For scan documents, the client defaults to `PDF (layer)`, which preserves the
scan and currently shows 0% size reduction; no OCR text layer is generated by
the diagnostic preview. A `PDF (text)` reduction is shown only when the API
supplies its dedicated per-format measurement; the client does not reuse
`document.reduction_percent` for that format. The preferred format comes from
`document.default_output_format` (`pdf_layer` or `pdf_text`). Per-format
measurements live in `document.output_formats.pdf_layer` and
`document.output_formats.pdf_text`, each with `generated`, `file_size_bytes`,
`reduction_percent`, and `size_reduction_basis`, with an optional `url` only
when generated. Scans default to `pdf_layer`; native-text and other documents
default to `pdf_text`. An ungenerated layer reports
`generated: false`, `file_size_bytes: null`, `reduction_percent: 0`, and
`size_reduction_basis: "not_generated_default_zero"`; the UI shows 0% for it.
The text format's value is shown only when it was generated and measured.
Artifacts marked `generated: false` are not resolved as usable URLs, even if a
legacy compatibility field such as `transcription.document.url` still
contains a URL.

```json
{
  "schema_version": 2,
  "document": {
    "word_count": 53,
    "source_language": "Polish",
    "reduction_percent": null,
    "size_reduction_basis": "transcription",
    "kind": "printed_scan",
    "mode": "scan",
    "processing_label": "Transcribed document",
    "original_preview": {
      "url": "/artifact/{job_id}/original.png",
      "mime_type": "image/png",
      "width": 900,
      "height": 1273
    }
  },
  "transcription": {
    "status": "needs_review",
    "preview": {
      "mode": "scan_text_fade",
      "source_text_url": "/artifact/{job_id}/scan-source-text.png"
    }
  },
  "translation": {
    "status": "needs_review",
    "target_language": "English",
    "estimated_word_count": 47,
    "reduction_percent": null,
    "preview": {
      "mode": "scan_text_fade",
      "source_text_url": "/artifact/{job_id}/scan-source-text.png",
      "target_text_url": "/artifact/{job_id}/scan-translation-text.png"
    }
  }
}
```

`transcription.preview.source_text_url` is always present for scan documents,
even when every translation fails, so the panel can still show the source text
next to a "Translation preview unavailable" placeholder.

## Native-text PDF

For native-text documents, `document.mode` is `native` and the right panel
shows two pages: the original first page followed by a preview rendered from
the translated rebuilt PDF. No text overlay or fade is used. When no
translation preview is available, the source page is still shown next to an
unavailable placeholder.

```json
"translation": {
  "status": "needs_review",
  "target_language": "English",
  "preview": {
    "mode": "native_pdf",
    "url": "/artifact/{job_id}/native-translation.png",
    "mime_type": "image/png"
  }
}
```

Transcription and translation also have separate UTF-8 `.txt` and PDF artifacts.
The source text uses the VLM draft when available, and translated text comes
from XLIFF, so the preview retains characters such as Polish `ł` and `€`.
Only the site-facing outputs are published; `/tmp/vlm_debug` remains diagnostic
data. `ready`, `needs_review`, and `error` are independent states for each
result. The current server reports `needs_review` until automatic review
criteria are set. It requires `DEEPL_AUTH_KEY` to create the default
translation; on failure it returns `translation.status: "error"` and still
returns the transcription and original preview.
